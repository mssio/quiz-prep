# Quiz Prep Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the GPT-written quiz site as a readable React app called Quiz Prep, and add named quizzes, score history, export/import and LaTeX math.

**Architecture:** All logic lives in pure, tested modules under `src/lib/`, with zod schemas as the single source of types. One React context plus a pure reducer holds the state and saves it to `localStorage`. Screens are TanStack Router file routes. Phase 1 (Tasks 1–9) proves the logic and quiz-taking against the old tests; phase 2 (Tasks 10–14) adds quiz management.

**Tech Stack:** Bun, Vite 8, React 19, TypeScript, TanStack Router, Tailwind 4, zod 4, KaTeX, @dnd-kit/core + sortable, Vitest 5, Biome.

**Spec:** `docs/superpowers/specs/2026-11-03-react-conversion-design.md`. Read it first. It holds the behaviour rules this plan doesn't repeat.

## Global Constraints

- App name is **Quiz Prep**. The name "Quiz Workspace" must not appear in the app. The "Q•" logo stays.
- `localStorage` key `quiz-prep:v1`, envelope `{version: 1, state: {quizzes}}`.
- Export file `quiz-prep-export.json`, header `{format: 'quiz-prep-export', version: 1, exportedAt, quizzes}`.
- Allowed new packages only: `zod`, `katex`, `@dnd-kit/core`, `@dnd-kit/sortable`, `@dnd-kit/utilities`, and dev `vitest`. No jsdom or testing-library: component tests use `renderToStaticMarkup` from `react-dom/server` in Vitest's node environment.
- No network requests at runtime. No CDN fonts or scripts.
- `dangerouslySetInnerHTML` appears only in `src/components/MathText.tsx`.
- Error messages, wording and copy not listed here are copied **verbatim** from the old source. The old site is gitignored, so always read it at the absolute path `/home/mss/code/sait/quiz-workspace/.private/gpt-generated/` (also when working in a worktree).
- Import app code through the alias: `#/lib/parser`.
- Readability is the point: small functions, plain names, no one-line tricks. No file over about 200 lines.
- `bun run check`, `bun run typecheck` and `bun run test` must pass at the end of every task.

## Review Focus

Cases the spec implies but doesn't spell out. Each has a test in the task named.

1. A learner changes a self-assessment after the score was recorded: the same history entry updates, with no duplicate. After Reset scores, changing it doesn't bring the entry back (Task 10).
2. The app is opened over plain `http` on a LAN or WSL address, where `crypto.randomUUID` doesn't exist: ids must still work (Task 1, `newId`).
3. The app is open in two tabs: a stale tab must not overwrite the other's changes with old data (Task 4 `replaceState`, Task 5 provider).
4. An import file is valid JSON with bad content, such as an answer pointing to a missing option or repeated question numbers: it's rejected and nothing changes (Task 11).
5. Upload edge cases: `NOTES.MD` in capitals is accepted, and a file that can't be read becomes an error row instead of stopping the whole batch (Task 2).

type Choice = { id: string; text: string }
// QuestionContent: discriminated union on `format`. All have number, prompt, explanation.
//   'single-choice'  options: Choice[]                 answer: string | null
//   'multi-select'   options: Choice[]                 answer: string[] | null
//   'true-false'                                       answer: boolean | null
//   'fill-in-blank'                                    answer: string[] | null
//   'short-answer'                                     answer: string | null
//   'matching'       left: Choice[], right: Choice[]   answer: Record<string, string> | null
//   'ordering'       items: Choice[]                   answer: Record<string, number> | null
type Question = QuestionContent & { id: string; quizId: string }
type ResponseValue = string | boolean | string[] | Record<string, string>
type Attempt = {
  id: string; questions: Question[]; order: string[]
  displayOrders: Record<string, (string | boolean)[]>
  responses: Record<string, ResponseValue>
  flags: Record<string, boolean>; assessments: Record<string, boolean>
  currentIndex: number; status: 'active' | 'submitted'
  isRetry: boolean; submittedAt: string | null
}
type HistoryEntry = {
  id: string            // the attempt's id
  submittedAt: string; questionCount: number; totalQuestions: number

}
type Quiz = {
  id: string; name: string; filename: string; title: string; course: string
  questions: Question[]; history: HistoryEntry[]; attempt: Attempt | null; addedAt: string
}
type WorkspaceState = { quizzes: Quiz[] }
```

```
at an opening $ (next char is not whitespace):

  if it has a non-space before it and no digit after it → math
